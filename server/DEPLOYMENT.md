# v20 後端準備與驗收

狀態：程式準備分支；未連接真實 PostgreSQL、未執行 SQL、未建立真實帳戶、未搬遷會員資料、未部署 Vercel，現有 GitHub Pages v19 不變。沒有採用或要求安裝已略過的 Supabase 外掛。

## 已準備的程式

- 獨立 Node 後端、PostgreSQL adapter、認證、隨機 session、密碼 salted scrypt、共用帳戶及來源檢查、登入限速、沒有自行註冊接口。
- 七個帳戶允許名單，不包含實際密碼或雜湊。只在受信任後端使用 `provisionAdmin()` 建立帳戶；不得把使用者提供的密碼、雜湊、私密金鑰或資料庫連線寫入公開 repository。
- 後端逐項檢查讀寫權限。前端限制只是方便操作，真正限制在 API 回覆資料之前執行。
- 原子交易、交易編號防重複、伺服器採用現行項目價格及分類、實收金額與畫面不同時拒絕結帳。後端連線錯誤不會切換成本機示範資料。
- 每250筆分頁讀齊全部紀錄；分頁期間資料版本改變會停止，不混合版本或截斷營業額。原始交易與營業額永不追溯重算。
- GitHub 前端可使用獨立 HTTPS 後端；未來 Vercel 已準備 `api/[...path].js`、`vercel.json`，但未進行真實部署驗證。

1. 洗剪吹、洗吹造型、單剪共同計次數，每宗完成消費最多一次，不按同單數量倍增；每10次獲一次9折。本單新獲優惠可立即使用，次數歸零後再累積。
2. 只有三款剪吹及／或產品，無消費、生日、介紹印花；加購產品滿600也不發印花。
3. 其他服務仍按每次滿600獲1印花，餘數不跨單累積。含其他服務時，加購產品按原有95折會員價加入計印花基礎；三款剪吹的金額不混入該基礎。
4. 達4印發一次9折資格，不扣走累積進度；繼續到8印發一次85折資格並重新計數，多出的印花留在下一輪。每個資格只能用一次，新資格本單可即時使用。
5. 生日月份及成功介紹朋友獎賞沿用原有規則，但只由其他合資格服務觸發。生日按香港曆年一次，介紹獎賞按介紹紀錄一次。
6. 以入會周年分會員年度：周年00:00（香港）到期，開始下一年度；滿8印不延長年度。2月29日入會在非閏年採2月28日。印花及印花優惠資格於該年度末到期；剪吹計次與剪吹優惠沒有另外加上一年限制。
7. 主管首頁及會員頁顯示14天內到期；新五個管理員首頁仍嚴格只有兩區，會員頁可查看到期狀態。

其中「每張單最多計一次剪吹」「會員周年續新年度」「優惠分別用於所屬類別、不疊加」「未用優惠保留至期限」是為了使規則可執行而採用的明確驗收口徑；正式啟用前應由負責人核對，不把它們當作過去交易事實。

- `joined_date` 是實際入會日期，與系統建立時間 `created_at` 分開；建立時間不被改寫，生日只保存月日。
- 已有新制優惠、調整或交易後，不允直接改入會日期而洗掉優惠，要另行核對。
- Howood 在原有資料裝置登入後，可先下載完整JSON備份，確認已保存，再按鈕匯入已確認的後端。匯入比對SHA-256；伺服器保留完整私有來源快照，不清除原本瀏覽器資料。
- 不會聲稱其他裝置的資料已合併或已找回。目標已有資料時拒絕覆蓋；同一來源重試可識別。
- 舊會員必須由 Howood／Sally 核對實際入會日期、新制起始進度及未用優惠；不能從舊「扣4／8印花」帳簿猜出新里程碑優惠是否用過。確認動作一次性並記錄操作者。未核對前停止該會員的新制結帳，舊歷史原樣可讀。
- 舊版消費項目、單價、折扣、實收、印花帳簿及營業額不重新計算。舊服務仍留作歷史參照，新選項使用已確認的30款服務價目。

## 接駁需要的設定（尚未取得）

由使用者選定並授權的 PostgreSQL 資料庫及 Node 後端平台；不要求任何外掛。不要在聊天或公開檔案張貼私密金鑰／資料庫密碼。

1. 在選定測試資料庫執行 `server/schema.sql`（目前未執行）。使用專用後端帳戶，確保私有schema沒有公開讀取途徑。
2. 受信任後端環境設定 `DATABASE_URL`；必要時設定 `DATABASE_SSL_CA`。TLS憑證及主機驗證保持啟用，不能用 `rejectUnauthorized:false`。
3. 設定 `KHAIR_ALLOWED_ORIGINS=https://mssallyct.github.io`；之後加入確定的 Vercel 前端來源。不得使用萬用字元。
4. 在受信任後端使用 `initializeBusinessState(pool)`，只初始化不存在的空資料；用 `provisionAdmin(pool,{username,password})` 安全輸入七個已指定帳戶的密碼。已存在帳戶不覆寫。程式沒有公開的帳戶建立接口。
5. 僅測試環境啟用 `KHAIR_BACKEND_ENABLED=true`。登入後讀寫session、資料庫transaction及來源限制必須實際驗證。
6. GitHub前端建置設定 `KHAIR_BACKEND_URL=https://已確認後端/api`；未來同站Vercel可設定 `/api`。建置時自動關閉 Demo Mode 並啟用 `requiresBackend`，缺連線不會退回空白本機資料。
7. 先用測試資料驗收，再核對、備份及匯入實際資料。需逐一確認七個帳戶、Sally匯出不含電話、直接呼叫設定／操作記錄API被拒、同單重試、4／8／10優惠、周年到期及跨裝置一致。
8. 實際平台須使用可信來源取得登入限速的用戶端IP；目前預設共用保守限額。亦需部署前設定session／限速表清理、資料庫自動備份、還原演練及正式權限審查。
